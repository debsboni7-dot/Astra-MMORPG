# ASTREA Unity client foundation

This is the native Unity project foundation for ASTREA. It lives alongside the existing browser prototype so the working web build and its tests are not discarded during the engine transition.

## Pinned toolchain

- Unity Editor: **6000.3.28f1 (Unity 6.3 LTS)**
- Render pipeline package: **Universal Render Pipeline 17.3.0**
- Main targets: Android first for device validation, then desktop. Console builds require platform-holder access and platform-specific modules.

Unity 6.3 LTS is the current LTS line and is recommended by Unity for live-service projects. URP is selected because it scales from mobile to high-end platforms.

## Open the project

Open this folder (unity/) as the Unity project root in Unity Hub. Unity Package Manager resolves URP from Packages/manifest.json.

After the first import:
1. Select **ASTREA > Rendering > Generate and activate URP asset**.
2. If Unity's menu command does not create the asset automatically, create it in Assets/Settings using **Assets > Create > Rendering > URP Asset (with Universal Renderer)**. Then run **ASTREA > Rendering > Activate selected URP asset**.
3. Set Android quality tiers separately from desktop tiers before device profiling.

## Current client foundations

- AstreaThirdPersonController: keyboard movement plus public joystick, touch-look and jump methods.
- AstreaVirtualJoystick, AstreaTouchLookArea and AstreaMobileInputBinder: touch movement, camera look and jump wiring for the generated starter-scene HUD. The scene builder creates the HUD automatically; it binds when a player prefab with AstreaThirdPersonController is present.
- AstreaGraphicsProfile: a conservative daylight, fog, ambient-light and mobile-shadow baseline for a scene bootstrap object.
- `com.unity.animation.rigging` 1.4.1: Unity 6.3-compatible rig constraints for future hand/weapon IK, foot placement and armor attachment adjustments.
- `AstreaMixamoImportPostprocessor`: configures the ASTREA character FBX as a Humanoid Avatar and imports FBX clips dropped into `Assets/Art/Animations/Mixamo/` against that Avatar when available. See `Assets/Art/Animations/Mixamo/README.md` for the manual Mixamo handoff.
- AstreaArmorLoadout: eight independent attachment slots for chest, back, left/right shoulders, left/right forearms, waist and legs.
- Assets/Editor/AstreaUrpSetup.cs: editor utility to create and activate a URP asset.

The armor source is generated by Blender in ../blender-workbench/build_armor.py. The Blender workflow exports native .blend, interchange .glb, Unity-importable .fbx, a PNG preview and five sets of 512px PBR maps (base color, metallic/roughness and normal). Its workflow copies the validated FBX, preview and texture PNGs into Assets/Art/Armor/. AstreaArmorModelPostprocessor applies consistent import settings. See ../docs/ART_DIRECTION.md for the material palette and visual standards. The FBX is not rigged or fitted to a production character yet; current geometry is a blockout and must be refined before production use.

## Zero-mandatory-spend policy

This project does not configure paid Unity Gaming Services, paid hosting, paid databases, or automatic billing. No cloud resources are provisioned by opening the project. The existing Node.js/PostgreSQL backend remains a development foundation; a public persistent MMORPG server still needs compute, storage and bandwidth and cannot be promised at zero cost.

GitHub Actions validates the project manifest, pinned editor version, source layout and Blender exports. The Unity Editor itself is not installed or licensed on the standard GitHub runner, so editor compilation, scene rendering and Android builds are not claimed as verified by CI yet.


## Combat foundation

- `AstreaCombatController` provides cooldown-gated melee input, a non-allocating overlap query, automatic child-Animator discovery, an optional `Attack` trigger and an animation-event hook for impact timing.
- `AstreaHealth` is a reusable local damage receiver with health-change and death events.
- The generated mobile HUD includes an Attack button wired to the combat controller when a player object with that component is present.
- This is a local combat prototype only. In a multiplayer build, hit validation, damage, cooldowns and health changes must be authoritative on the game server; clients must not decide final damage.


## Input, camera and streamed content

The Unity 6.3 project now includes the released Unity packages below:

- Input System 1.20.1: keyboard (WASD), mouse, gamepad movement/look, jump and attack. `AstreaInputRouter` feeds the existing character/combat APIs. The mobile joystick and touch-look UI remain separate input sources and continue to work alongside physical devices.
- Cinemachine 3.1.7: the starter-scene builder creates a Cinemachine Brain on the render camera and a third-person Follow + Rotation Composer camera targeting the player camera pivot.
- Addressables 2.10.3: `AstreaAddressableLoader` instantiates content by address key and releases tracked instances when unloaded or when its owner is destroyed.

### Addressables authoring

Mark a prefab as Addressable in the Unity Inspector and assign a stable key, for example `world/astrea/plains/settlement` or `characters/npc/merchant_01`. Add the required Addressables groups and build the content catalog from the Unity Editor before using remote content. The runtime loader does not configure hosting or publish catalogs; use a CDN/object store only after its costs and access controls are agreed. Local Addressables builds can be tested without paid services.

### Important validation notes

These integrations are source- and package-level setup. GitHub Actions checks project metadata and key source contracts; it does not run the Unity Editor, resolve the Unity Package Manager dependency graph, generate an Addressables catalog, or verify camera framing on a device. The project still needs a real Unity 6.3 Editor import/build and Android device test. Input rebinding UI, controller glyphs, Cinemachine obstruction handling and production content catalog hosting are future tasks.


## Animation and visual effects foundation

- `AstreaAnimationDriver` maps planar movement, grounded state and vertical velocity to Humanoid Animator parameters: `Speed`, `MoveX`, `MoveY`, `Grounded`, `VerticalSpeed`. It exposes `Attack`, `Hit` and `Dead` animation events through Animator parameters. Create an Animator Controller with these exact parameter names and assign Mixamo clips before expecting visible character animation.
- `AstreaVfxLibrary` pools authored ParticleSystem prefabs by key and enforces a hard per-effect instance cap. When all instances are active, additional requests are rejected instead of creating unbounded objects. The melee combat controller requests `melee_impact` only when it confirms a damageable target.
- The editor command **ASTREA > VFX > Create Starter VFX Library** creates ten editable starter particle prefabs (melee impact plus fire, water, wind, earth, frost, lightning, nature, light and dark) and connects them to an `AstreaVfxLibrary` on the player in the currently open starter scene. Particle materials are saved as reusable `.mat` assets rather than transient in-memory materials.
- `AstreaSpellVfxController` maps elemental names to those pooled VFX keys. Spell gameplay should call it only when a spell is released or confirmed to hit; it does not implement spell damage or networking.
- The editor command **ASTREA > Animation > Build Starter Animator Controller** scans imported clips in `Assets/Art/Animations/Mixamo/`, builds a reusable locomotion/airborne/combat controller, and assigns it to Animators in the open scene with root motion disabled. The scene assignment loop is covered by the Unity foundation regression checks. It detects clips by names containing Idle/Breathing, Walk, Run/Sprint, Jump, Fall, Land, Attack/Slash/Sword, Hit/Hurt/Damage and Death/Die. Missing clips are skipped with warnings.
- These generated particles are a first-pass visual language, not final high-end VFX. Replace/refine them with authored flipbook textures, mesh particles, shader effects, trails, hit flashes, elemental decals and optimized mobile variants. Keep effects pooled and cap particle counts on Android.

### Mixamo animation setup

After importing a rigged Humanoid FBX and its clips into `Assets/Art/Animations/Mixamo/`, create/assign an Animator Controller to the character Animator. Use the exact parameter names above. Add an animation event named `AnimationEvent_ApplyMeleeHit` at the weapon contact frame for each melee attack clip; without this event, the attack animation will not apply damage while an Animator is present. Add transitions for locomotion, jump/fall/land, attack, hit reaction and death. The current driver supplies parameters and triggers; it does not invent or generate animation clips. The generated controller is a starter graph: review transitions and clip selection in Unity Editor, and add `AnimationEvent_ApplyMeleeHit` to each melee clip at the actual contact frame.

### Unity elemental spell prototype

- `AstreaSpellCombatController` now provides the nine starter spell definitions with the costs and cooldowns documented in `docs/magic-combat-spells-v1.md`. It regenerates mana, checks range/cooldown/mana before spending, applies damage to `IAstreaDamageable` targets, heals the caster for nature/light and grants a timed damage-absorbing earth shield.
- Keyboard **K**, gamepad **North/Y**, and the generated mobile **MAGIC** button cast the current starter spell (fire). The element is passed as a parameter to `TryCast`, so an element selector can be connected later.
- Elemental VFX play at the cast point and confirmed target positions. These are pooled first-pass particle effects. Burning, slow, freeze, stun and purification gameplay effects, race-specific spell permissions/bonuses, authoritative multiplayer validation and a spell-selection HUD are not implemented in this Unity slice yet.
- The Unity spell runtime is a local prototype; it does not replace the existing browser/server combat implementation.

### Cloud editor build

The workflow `.github/workflows/unity-android-build.yml` runs a licensed Unity 6.3 Editor session, generates the starter scene/VFX/Animator assets, and builds an Android APK. It is manual and guarded by an explicit confirmation input. It requires a Unity Personal/Pro license file stored as the GitHub repository secret `UNITY_LICENSE`; this is a Unity licensing prerequisite, not a paid hosting service. The build deliberately fails if the humanoid FBX is absent, rather than producing an APK that looks playable but has no player character.

The character generation workflow `.github/workflows/meshy-generate-humanoid.yml` is separately guarded and can consume up to 30 Meshy credits. It has not been triggered. Do not launch it until the credit spend is explicitly approved.
